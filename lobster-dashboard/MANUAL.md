## 1. 什么是龙虾集团

### 📌 简介

龙虾集团是一个**基于 AI Agent 的虚拟团队协作系统**。它模拟真实公司的组织架构，将一个 AI 分成 6 个专业部门，像真正的团队一样协作完成任务。

你只需要下达一句话任务，龙虾集团会自动完成：**任务拆解 → 分工执行 → 交叉校验 → 汇总输出**。

### 🎯 设计理念

| 理念 | 说明 |
|------|------|
| 专业分工 | 每个部门只做擅长的事，避免"一个人干所有" |
| 流程驱动 | 标准化6阶段流程，确保不遗漏关键步骤 |
| 交叉校验 | 质检部独立审核，避免自己写自己改 |
| 透明可控 | 经营驾驶舱实时展示任务状态和健康指标 |

### 🔧 适用场景

- **复杂任务处理**：需要调研+策划+执行的多步骤任务
- **项目管理**：从零搭建一个完整项目
- **内容生产**：文案、社媒内容、品牌策划
- **技术开发**：代码编写、系统部署、自动化脚本
- **市场调研**：行业分析、竞品对比、数据整理
- **方案策划**：商业计划、营销方案、决策建议

## 2. 组织架构

### 🏢 六大部门

| 部门 | 角色 | 职责 | 核心能力 | 适合任务 |
|------|------|------|----------|----------|
| 🎯 指挥部 | LeadAgent | 任务拆解、统筹调度、优先级决策、最终交付 | 全局视野、任务编排、跨部门协调 | 所有任务的起点和终点 |
| 🔍 情报部 | ResearchAgent | 信息搜集、市场调研、竞品分析、事实核查 | 搜索引擎、数据抓取、信息整合 | 调研、数据收集、事实验证 |
| 🧠 策略部 | StrategyAgent | 方案设计、商业分析、决策建议、战略规划 | 逻辑推理、框架思维、方案对比 | 方案设计、策略分析、决策 |
| ⚙️ 工程部 | EngineerAgent | 代码开发、技术实现、系统运维、自动化 | 编程、调试、部署、架构设计 | 代码、脚本、部署、技术问题 |
| ✍️ 内容部 | ContentAgent | 文案撰写、品牌内容、创意设计、社媒运营 | 文案功底、视觉审美、内容策划 | 文案、推文、小红书、品牌 |
| ✅ 质检部 | ReviewAgent | 纠错审校、质量验收、优化润色、风险预警 | 细节把控、逻辑校验、标准执行 | 所有产出物的最终审核 |

## 3. 任务流程

### 📋 标准流程（6阶段）

```
用户任务 → Phase1接收 → Phase2情报 → Phase3策略 → Phase4执行 → Phase5质检 → Phase6交付
```

| 阶段 | 负责部门 | 做什么 | 输入 | 输出 |
|------|----------|--------|------|------|
| Phase 1 | 指挥部 | 接收任务、分析类型、拆解子任务、设优先级 | 用户任务描述 | 任务拆解清单 |
| Phase 2 | 情报部 | 搜集背景信息、整理资料、事实核查 | 调研需求 | 情报简报 |
| Phase 3 | 策略部 | 制定执行方案、评估风险、提供备选 | 情报简报 | 方案文档 |
| Phase 4 | 工程部/内容部 | 按方案执行，产出具体成果 | 方案 + 需求 | 产出物 |
| Phase 5 | 质检部 | 审核准确性、逻辑、格式，风险预警 | 各部门产出 | 审核通过/修改意见 |
| Phase 6 | 指挥部 | 汇总整合、最终审核、交付用户 | 所有产出 | 最终交付物 |

### ⚡ 快速通道（紧急任务）

跳过情报和策略阶段，直接执行：

```
用户任务 → 指挥部 → 工程部/内容部 → 质检部 → 指挥部交付
```

**适用场景**：简单明确的任务、紧急需求、不需要调研的执行类任务。

> ⚠️ 注意：快速通道可以跳过调研和策划，但**质检不可跳过**。

### 🔍 纯调研流程

只做信息搜集，不执行：

```
用户任务 → 指挥部 → 情报部 → 质检部 → 指挥部交付
```

**适用场景**：市场调研、竞品分析、事实核查、信息搜集。

## 4. 如何下达任务

### 💡 任务格式建议

高效下达任务的公式：

```
【做什么】+【要求/范围】+【期望产出】
```

越具体越好。模糊的指令会增加沟通成本。

### 📝 示例任务

| 类型 | 示例 | 涉及部门 |
|------|------|----------|
| 🔍 调研类 | 「帮我调研2026年国内AI Agent市场，包括主要玩家、市场规模、技术趋势，输出一份调研报告」 | 指挥→情报→质检 |
| 🧠 策略类 | 「给我做一份小红书账号冷启动方案，目标3个月涨粉1万，预算5000元」 | 指挥→情报→策略→质检 |
| ⚙️ 技术类 | 「开发一个Python脚本，自动监控网站可用性，异常时发送通知」 | 指挥→工程→质检 |
| ✍️ 内容类 | 「写一篇关于AI办公效率提升的小红书文案，风格轻松有趣，1000字左右」 | 指挥→内容→质检 |
| 🚀 综合类 | 「从零搭建一个团队知识库系统：调研方案→选型→部署→写使用文档」 | 全部门协作 |

### 🔴🟡🟢 任务优先级

| 优先级 | 说明 | 流程 |
|--------|------|------|
| 🔴 紧急 | 需要立即处理 | 快速通道，跳过调研策划 |
| 🟡 普通 | 正常排期处理 | 标准6阶段流程 |
| 🟢 低优 | 有空再做 | 标准流程，排队执行 |

## 5. 经营驾驶舱（Dashboard）

驾驶舱是龙虾集团的**实时监控面板**，让你一眼掌握团队运行状态。

### 🖥️ 面板区域

| 区域 | 位置 | 说明 |
|------|------|------|
| 顶部标题栏 | 最上方 | 集团名称、部门列表、更新时间 |
| KPI卡片行 | 标题下方 | 5个核心指标卡片 |
| 部门视图 | 中部左侧 | 6部门任务状态表格 |
| 风险告警 | 中部右侧 | 异常任务和风险提示 |
| 任务明细 | 底部左侧 | 最近25条任务记录 |
| 文件快查 | 底部右侧 | 组织文件快速查看入口 |

### 📊 KPI指标含义

| 指标 | 含义 | 正常范围 |
|------|------|----------|
| 健康指数 | 系统整体健康度，满分100 | ≥60 为正常，🟢100=完美 |
| 已成交提案 | 已完成并交付的方案数 | 越多越好 |
| 任务成功数 | 成功完成的任务总数 | 持续增长 |
| 步骤成功数 | 各步骤成功执行次数 | 关注失败数 |
| 风险告警数 | 当前异常和阻塞数量 | 🔴0=最佳 |

> **健康指数计算**：`100 - (任务失败数 × 10) - (步骤失败数 × 2)`

### 📋 部门视图怎么看

表格展示每个部门的：**总量 / 成功 / 运行中 / 排队 / 失败 / 最近任务**

- 全是0 = 该部门尚未执行任务
- 运行中 > 0 = 正在工作
- 失败 > 0 = 需要关注

### ⚠️ 风险告警怎么看

- 「暂无异常，系统稳定 ✅」= 一切正常
- 出现红色条目 = 有任务失败或阻塞，需要干预

## 6. 文件系统

龙虾集团的运行依赖以下核心文件：

| 文件 | 用途 | 修改频率 |
|------|------|----------|
| `ORG.md` | 组织架构定义——部门、职责、角色、能力 | 低（架构变动时） |
| `SOP.md` | 标准作业流程——6阶段流程和协作规则 | 低（流程优化时） |
| `TASK_ROUTING.json` | 任务路由规则——关键词触发、流程路径定义 | 中（新增任务类型时） |
| `GOALS.md` | 目标管理——当前目标和里程碑追踪 | 高（目标更新时） |
| `METRICS.md` | 指标定义——健康指数等KPI的计算规则 | 低（指标调整时） |
| `CHANGELOG.md` | 变更日志——记录所有重要变更 | 高（每次变更后） |
| `index.html` | 经营驾驶舱——可视化监控面板 | 中（数据更新时） |

### 📂 如何查看和修改

- **查看**：直接打开对应文件，或通过驾驶舱底部「文件快查」区域点击查看
- **修改**：用文本编辑器打开对应文件编辑即可
- **建议**：修改前先备份，修改后在 `CHANGELOG.md` 记录变更

## 7. 最佳实践

### 🏆 怎么用效果最好

1. **任务描述要具体**：说清楚目标、范围、期望产出格式
2. **善用优先级**：紧急任务走快速通道，复杂任务走标准流程
3. **信任流程**：让每个部门做完自己的事，不要跳步骤
4. **关注驾驶舱**：定期查看健康指数和风险告警
5. **迭代优化**：根据产出质量调整任务描述方式

### ❓ 常见问题 FAQ

**Q1：任务太复杂怎么办？**
> 交给指挥部就行。它会自动拆解成子任务分配给各部门。你只需要描述最终想要什么。

**Q2：能不能跳过某些部门？**
> 可以。紧急任务可以走快速通道（跳过情报和策略），纯调研可以只走情报部。但质检部**不能跳过**。

**Q3：对产出不满意怎么办？**
> 把具体不满意的地方反馈回来，指挥部会重新调度修改。越具体的反馈，修改效果越好。

**Q4：同时下多个任务可以吗？**
> 可以。指挥部会根据优先级排队处理。建议标注优先级避免重要任务被延后。

**Q5：怎么知道任务进度？**
> 查看经营驾驶舱的「任务明细」区域，或关注部门视图中各部门的运行状态。

**Q6：文件被改坏了怎么办？**
> 重要文件有 Git 备份。可以通过版本控制回滚到之前的状态。

### ⚠️ 注意事项

- 质检部对所有产出有**否决权**——发现问题会打回重做
- 任何部门发现任务偏离目标，会**立即上报**指挥部
- 跨部门协作由指挥部统一协调，不要绕过指挥部直接指派
- 修改配置文件后记得更新 `CHANGELOG.md`

## 8. 快速上手

### 🚀 三步开始使用

| 步骤 | 操作 | 说明 |
|------|------|------|
| Step 1 | 打开经营驾驶舱 | 打开 `index.html`，确认系统状态正常（健康指数100） |
| Step 2 | 下达你的第一个任务 | 用自然语言描述你想做的事 |
| Step 3 | 等待交付 | 关注驾驶舱进度，收到交付物后给出反馈 |

### 🎬 第一个任务示例：完整流程走一遍

假设你的任务是：**「写一篇关于AI提升工作效率的小红书文案」**

```
📌 Phase 1 — 指挥部接收
   → 分析：这是内容类任务，需要情报支撑
   → 拆解：情报部调研 → 内容部撰写 → 质检部审核

📌 Phase 2 — 情报部出动
   → 搜索当前小红书AI相关热门内容
   → 整理爆款文案的共同特征
   → 输出：《AI效率类内容调研简报》

📌 Phase 3 — 策略部规划（如需要）
   → 根据调研确定文案方向和风格
   → 输出：内容策略建议

📌 Phase 4 — 内容部执行
   → 根据调研和策略撰写文案
   → 输出：完整小红书文案（标题+正文+标签）

📌 Phase 5 — 质检部把关
   → 检查文案逻辑、错别字、平台规范
   → 优化标题吸引力和标签选择
   → 输出：审核通过 ✅

📌 Phase 6 — 指挥部交付
   → 汇总所有产出，整合为最终交付物
   → 交付给你 🎉
```

就这么简单。你只说了一句话，龙虾集团 6 个部门自动协作完成了整个流程。
